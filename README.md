# dsh-world

给 DSH 里的陪伴角色一个会记得、会生活的世界。

装上以后，她会记得你们在每个窗口里说过的话；有一个自己的家，自己决定接下来做什么、做到几点，想你了会主动来找你；每天晚上回想这一天，写日记，也改写一份关于自己的自述。开关和人设都在 DSH 设置里的「世界控制台」，由你掌握。

插件只用 DSH 原本开放的扩展接口，不改宿主的一行代码。

当前版本 **0.6.0**。完整变更、升级步骤和已知限制见 [更新日志](CHANGELOG.md#060--2026-10-28)。

## 她能做到什么

### 记得：像人一样记

- **近期记忆**：你们最近数轮的对话原文，每次开始对话和每次压缩之后都放在她眼前，谁、什么时候、说了什么，一字不差。轮数在控制台里填，默认 200。
- **日记**：人生里重要的事，她自己写进日记，一天一篇。这是她的长期记忆。
- **我是谁**：她写给自己的一份自述，随着她变化而改写。每晚回顾前，插件会留一份当时的版本，改过的都找得回来。
- **范围内的原文留着**：按天归档用户和助手的正文。近期记忆以外的事，她可以自己去翻。

日记和自述都由她自己动笔，插件从不替她写。

**为什么不用向量库或记忆系统？** 一个人的生活，量没有那么大。在这个量级上，把原文留在眼前、需要时按原话去找，比切碎了再拼回来更准，也少一道会出错的环节。可参考：

- Chan et al., 2024. *Don't Do RAG: When Cache-Augmented Generation is All You Need for Knowledge Tasks*. arXiv:2412.15605
- Sen et al., 2026. *Is Grep All You Need? How Agent Harnesses Reshape Agentic Search*. arXiv:2605.15184

### 生活：她自己的日子

- **家**：她有一个自己的会话「<名字>的家」，和一个房间（工作目录），在里面过自己的日子。
- **自己定节奏**：她说好接下来做什么、做到几点，到点了再决定继续还是换一件。什么都不定，就休息到第二天早上。
- **主动找你**：想你的时候，她可以把一句话送到你面前（Windows 系统通知，或你接上的桌宠等程序）。
- **每日回顾**：每天晚上 23:00，她回想当天的聊天和做过的事，写日记，更新「我是谁」。
- **每天额度**：可以给家里每天的花费设个上限，超过了会提醒她一次，由她自己决定收尾。
- **大事先问**：删改房间外的文件、装软件、花钱、以你的名义对外发消息等，约定好先问你。

### 世界控制台：开关在你手里

DSH 设置里的「世界控制台」：

- **开始 / 停止**：按下开始，她才住进来；按下停止，记忆、人设和生活线一起安静下来，家还在，等你回来。
- **人设**：分层写她是谁：名字、她是谁、性格、说话方式、愿景、补充，旁边实时预览她读到的样子。
- **世界提示词**：你想对她说的话，以及她的世界的说明。
- **概览与记录**：她此刻在做什么、下个闹钟、近期记忆有多少轮、今天花了多少；还有活动记录、日记和压缩记录。
- **接入开关**：配置里启用了微信（`wechat: true`）或 QQ（`qqNative.enabled: true`）后，概览里有一张「接入」卡片，各有一个开关，立即生效、无需重启，状态记在 `world.json`。微信开着才注册 `wechat_chats`、`wechat_history`、`wechat_send`、`wechat_delivery` 并拉起适配器（配了 `wechatAdapter` 时），关掉就撤掉；QQ 开着才连上那条 OneBot 通道、显示 QQ 卡，关掉就断开这条连接、把卡收起来。微信默认开；**QQ 默认关**——它依赖 `@snowluma/sdk`（声明在 `optionalDependencies` 里），不开就不加载那套代码，没装 SDK 也不影响插件本身。
- **归档范围**：默认 `workspace`，归档家所在工作区的普通会话，包含独立微信群会话；`home` 仅当前家会话。保存范围后提示重启，重启前沿用原范围。启动时分页回扫所选范围内的会话日志，按消息实际时间重选最近配置轮数，下次请求前替换旧记忆块；没有时间过期。旧归档保留，范围外记录不再注入。旧配置 `world` 迁为 `workspace`。

> **人设留空时的默认行为**：控制台人设全部留空时，默认沿用宿主或当前预设在系统提示词中配置的人设，插件不额外注入自定义人设。控制台不会自动读取并回填系统人设，因此界面留空不代表她原有的人设丢失。

> **人设槽位冲突（已知限制）**：当前预设已在同一会话作用域注册系统人设槽位时，插件会保留预设人设，再追加控制台人设，并在控制台健康状态中提示；目前尚未统一替换原槽位。两份人设会同时进入系统提示词，内容不一致时可能互相影响。

> **保存人设的生效时机（已知限制）**：保存会立即更新人设文件和控制台预览，但不会立即刷新已有会话的系统提示词。已有会话需等下一次成功压缩，或重新加载插件／重启 DSH 后，才读取保存后的内容；新建且匹配该世界预设的会话会直接读取新人设。

> **会话加入工作区后的记忆块（`workspace` 范围）**：加入操作不会立即回扫其全部历史，运行中的新消息会增量归档。
>
> 1. **旧会话没有记忆块**：加入工作区后，首次继续对话可以生成。
> 2. **旧会话已有记忆块**：继续复用，加入操作不会立即重建。
> 3. **重启后**：会补入尚未打开的会话历史，在下次请求前重建或替换旧块，每个会话保持一个有效记忆块。
>
> 要完整纳入新加入会话的历史内容，请重启 DSH；已有记忆块也会在压缩后等刷新时机更新。`home` 范围仍只归档当前家会话。

> **缩小范围与每日回顾**：旧归档和每日导出文件会保留，近期记忆按当前范围过滤；每日回顾仍读取当天已有的导出文件，尚未对其中旧的较大范围记录再次过滤。

### 只留下你们之间的话的压缩

对话太长需要压缩时，dsh-world 自带的压缩方式会去掉工具调用的过程，把你们之间的交流整理成一段摘要。她记住的是你，不是那些命令。

### 桌宠和其他程序

dsh-world 开放了一个本地的「桥」：桌宠之类的程序可以把你说的话送进她的家，也可以接收她的回复和主动找你的话。协议见文末。

微信作为独立模块接入同一个家，使用她的独立账号收发指定私聊或群聊。她可用 `wechat_chats` 查询已配置目标，用 `wechat_history` 主动分页查看群消息，无需等别人 @；读完以同一个 `chatId` 调用 `wechat_send` 自主联系对方或回复消息，文字、图片和表情共用同一发送队列；`wechat_delivery` 查询确认结果。普通最终回答不会自动转发到微信。Windows 适配器和配置步骤见 [微信模块](src/ecosystem/wechat/windows/README.md)。B 站尚未接入。

> **微信支持版本**：目前仅适配 **Windows x64 微信 `4.1.15.13`、`4.1.15.56` 的指定构建**。适配器会核对 `Weixin.dll` 的文件大小和 SHA256；其他构建（包括版本号相同但文件指纹不同的构建）会在加载原生桥前被拒绝。macOS、Linux 客户端暂不支持。升级微信前请确认新构建已有适配；各版本的实测范围见 [微信模块](src/ecosystem/wechat/windows/README.md)。

> **微信图片接收**：私聊普通图片会先缓冲最多 3 秒，合并紧随的同一发言人的一条说明文字后进入模型，每轮最多两张图，更多图片留到后续轮次。开始处理后才到达的文字排到下一轮，继续使用同一会话已有的图片上下文。群聊仍需真实 @ 她才触发看图。图片及附件引用只进入对应会话总日志，不自动写入共享记忆块；合并的真实文字按原归档范围保存，是否另行留存图片中的信息由她自己判断。缓存不可用时明确标记未读取，不操作界面下载。

> **微信风控与账号风险**：当前桥不是微信官方 API，接收端解密读取本地消息数据库，发送端向微信进程加载 DLL 并调用内部函数，存在账号功能受限或封禁风险。微信安全中心 [2026 年 1 月 29 日公告（媒体转载）](https://www.thepaper.cn/newsDetail_forward_32493057) 将违规获取聊天记录、联系人数据，以及通过模拟按键、自动化脚本操控微信等列为治理内容。仅用于家庭群、低频聊天，或改用 Computer Use，都不能保证账号安全；公开资料没有可靠的封号概率或安全发送阈值。

> **微信表情包接收**：私聊里你发来的原生表情包会按消息中的地址从腾讯 CDN 下载，md5 与消息一致才接受，并取第一帧作为图片交给她；这是适配器主动联网的功能，可在适配器配置里写 `"fetchStickers": false` 关闭，读取失败时她会看到明确的“未读取”原因。动图只取第一帧；群聊里的表情包目前不会交给她，群里发表情包后再 @ 她，她只能收到触发文字和其他已支持的上下文。原生表情包也不会进入插件的记忆归档。

> **视频号与朋友圈（预留）**：目前聊天中分享的视频号卡片会被跳过，不进入她的会话或共享记忆；收到卡片后没有回复，不代表微信监听掉线。视频号需要另行接入卡片解析和视频内容读取。朋友圈的浏览、发布也需要独立的操作能力，现有私聊／群聊发送接口不能发布朋友圈。这些能力暂只记录为微信模块的后续扩展，尚未实现。

> **微信退出重开**：保持适配器运行，退出微信后它会暂停收发并等待；她原来的账号重新登录后，会自动重新绑定进程并沿用消息游标恢复监听，无需重启 DSH。若退出发生在消息处理或发送途中，且结果尚未确认，则停止并保留待核对记录，不会自动重复回复；按微信模块中的 `Acknowledge` 流程核对后恢复。

> **微信首次接入与升级**：开启插件的微信开关本身不会启动 Windows 适配器；可手动启动，或在配置里写 `wechatAdapter` 让插件随微信模块启动和停止它（见适配器 README）。无论哪种，都需要配套适配器并完成账号及聊天目标注册后，微信工具才可使用。这套原生桥不依赖 `dsh-plugin-weixin` 或 iLink。升级插件和适配器后，两者均需重启，不能让旧适配器进程继续运行新版协议；保留原配置、游标和回执。

> **QQ 走插件自己那条原生通道**：插件直接连 SnowLuma 提供的 OneBot WebSocket，自己收、自己发（代码在 [`src/ecosystem/qq-native/`](src/ecosystem/qq-native/index.ts)），中间没有第二个进程，也不需要别的 QQ 实现。SnowLuma 负责登录 QQ 并对外提供 OneBot 的 HTTP／WS 服务；它按自己的 EULA 不许被自动化脚本部署，装法与参数怎么拿见 [INSTALL.md](INSTALL.md)。这条通道的配置都在 profile 的 `cordis.patch.yml` 里（见下文「设置」），控制台上的临时开关存在世界目录的 `qq-native.json`，主动开口的账存在 `qq-proactive.json`。

> **QQ 的记忆与开关**：QQ 消息由这条通道送进家里，插件没有为它做微信那样的渠道身份。按 `bindHomeSession`（默认 `owner`），主人的私聊用她的家会话，因此按普通家会话归档；每个群各挂一个独立会话（标题形如 `QQ · <群名>`），挂在她的房间工作区下、用同一个 `agentPreset`——所以在默认的 `archiveScope: workspace` 下，**群里的对话和微信群一样会进归档、进记忆块**，归档里只有会话、没有渠道标记。写 `none` 时私聊也另建一个这样的独立会话。群里的消息默认只有被叫到才接话，其余只进本轮上下文、不开口也不花额度。控制台「接入」里的 QQ 开关决定这条通道连不连。微信开关则会立即注册或撤掉 `wechat_chats`、`wechat_history`、`wechat_send`、`wechat_delivery`，并拉起或停止适配器。两个开关默认开，没在配置里启用的模块不能从控制台打开。

外部生态接入代码统一放在 [`src/ecosystem/`](src/ecosystem/README.md)：`wechat/` 包含微信宿主模块、Windows 收发适配器和原生桥；`qq-native/` 是插件自己连 OneBot 的那条 QQ 通道（`qq/` 里是与它配套的控制台接口和 SnowLuma 控制台那扇门）；`shared/` 保存通用身份协议、群会话路由与消息出口；`bridge/` 为桌宠等本地程序提供通用桥。后续平台在同一目录下独立扩展，核心记忆、人设和生活线保持独立。

微信原生发送引擎单独适用非商业许可，详见该模块的许可说明。

### QQ

QQ 走插件自己那条原生通道：直接连 SnowLuma 开出来的 OneBot WebSocket，收文本、发文本，中途没有别的进程。代码在 [`src/ecosystem/qq-native/`](src/ecosystem/qq-native/index.ts)。

在 profile 的 `cordis.patch.yml` 里打开 `qqNative`（`enabled: true` 只是允许它存在）、再到控制台「概览 → 接入」把 QQ 拨开、填上 WS 地址与 token、加上白名单之后，控制台里会多一张 QQ 卡片：连着哪个地址、收过几个会话、发过几条、挡下几条、会自己回还是只看不回、群规则，一眼看到；卡上还能直接拨「会自己回话 / 只看不回」和主动开口的两个开关，也能刷新、打开 SnowLuma 控制台。没配 `qqNative.enabled` 的时候这一块整个不出现，行为跟以前一样。

参数不对不会崩，只会连不上：卡上会把原因写在 `lastError` 里（比如 `WS 错误: Unexpected server response: 401`，说明填的是 HTTP 那份 token，该换成 WebSocket 那份）。QQ 卡只在通道启用、世界已经开始时出现。

**群里默认只接被叫到的**（`groupTrigger: mention`）：被 @、引用她刚说过的话、或文本命中 `groupKeywords` 才算叫她，其余消息只进本轮上下文，不开口也不花额度；写 `all` 就是每句都接，代价是群里每一条都会让她跑完一轮。`bindHomeSession` 决定谁和她的家会话共用一个入口，默认 `owner`。**主动开口**（`proactive`，默认关）让她自己隔一阵子找时机给主人发一句；规则、演练模式与每日额度见 [INSTALL.md](INSTALL.md)。

卡上那个「打开 SnowLuma 控制台」的按钮，读 `snowlumaHome` 下 `config/runtime.json` 里的地址与端口，带着一次性登录票据打开系统浏览器——第一次要先填一次 SnowLuma 的面板密码，之后记在世界目录的 `panel.json` 里（权限 600），不用再输。

**给别人的接入步骤**：从装插件到填 token 到验证，一步一步写在 [docs/QQ-接入步骤.md](docs/QQ-接入步骤.md) 里——那份是给「替用户装插件的人或 AI」看的，可以照着念。里面也标了哪几步只能用户本人动手（SnowLuma 自己的 EULA 不许脚本安装）。

**看门狗（2026-10-28 起做进插件）**：插件自己盯着这条线——每 30 秒探一次 `wsUrl` 的端口，不通就按 `snowlumaHome` 把 SnowLuma 拉起来（优先借它自己的计划任务，没有就直接起进程）。以前这活靠 `~/.dsh/tools/snowluma-watchdog.ps1` 加一个 Windows 计划任务干，别人装插件还得手动建一次；现在不用了，插件在就盯着。拉不起来只把原因记在卡片上（`lastError`），不反复刷日志。`qqNative.supervise: false` 可以关掉它自己动手。

卡片上那个「拉起 SnowLuma」是手动那一条：SnowLuma 没起、你又想立刻叫醒它的时候按一下，比等下一轮探测快。它和看门狗走同一条路（`startSnowluma`），所以按下去的结果和看门狗自己拉是一样的。

## 安装

需要 DSH 桌面版，世界控制台和生活线都依赖它。

**最省事的办法**：把这个仓库地址交给她，让她照 [INSTALL.md](INSTALL.md) 自己装。那份说明是写给模型看的——每一步都有命令、判定和失败对照表，连同 QQ 怎么接进来、哪两个动作必须人来做，一路写到底。

**自己装**：

```powershell
npm ci
npm pack
```

用 DSH 自带的 pnpm 把生成的 `dsh-world-*.tgz` 装进你的 profile。不要用 `link:` 指向项目目录，否则会加载项目自己的一份 Cordis。装好后重启 DSH，打开设置里的「世界控制台」，按需填写人设，按「开始」。

也可从 [CI](.github/workflows/ci.yml) 对应运行的 Artifacts 下载检查通过的编译安装包；Windows 和 Linux 分别提供产物。本机复现检查的命令见 [贡献协议](CONTRIBUTING.md#ci-与安装包验证)。

**换用只留对话的压缩方式**（可选）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-tool-free-compaction.ps1 -profilePath '<你的 DSH profile 目录>'
```

脚本会把 profile 里原版的压缩条目换成 `dsh-world/compaction`，并留一份备份。

## 设置

大多数东西在世界控制台里改。其余的写在 profile 的 `cordis.patch.yml` 里，按 id 覆盖插件那一行，只写想改的项：

```yaml
- id: dsh-world
  name: dsh-world
  config:
    companionName: 小鱼          # 她的名字（控制台人设里写了名字时以人设为准），默认 TA
    partnerName: 伙伴            # 她对你的称呼，默认 伙伴
    worldId: default             # 世界名；换一个就是另一个世界、另一份记忆
    agentPreset: standard        # 她所在的预设
    timeZone: Asia/Seoul         # 默认系统时区
    life: true                   # 生活线，默认开启
    archiveScope: workspace      # workspace：家的工作区；home：仅当前家会话
    fallbackWakeTime: '09:00'    # 没定闹钟时，早上几点叫醒她
    diaryDir: C:/path/to/日记    # 日记目录，默认在世界目录里
    toast: true                  # 主动找你时发 Windows 系统通知
    bridge: false                # 打开本地的桥
    wechat: false                # 打开独立微信接口，需另行启动 Windows 适配器
    outlets: []                  # 接收她的话的本地程序，见文末
    allowedHosts: []             # 通过反向代理从局域网访问控制台时，放行的域名或 IP
    qqNative:                    # 插件自己连 OneBot（原生通道）；不写这一块就是不接 QQ
      enabled: false             # 打开通道：连上、控制台里出 QQ 卡
      wsUrl: ws://127.0.0.1:3003 # OneBot 的 WS 服务地址（不是 HTTP 那个）
      accessToken: ''            # OneBot WS 服务端自己的 token，与 HTTP 那份不是一码事
      allowPrivate: []           # 谁能私聊她；留空 = 谁都不理
      allowGroups: []            # 群白名单
      autoReply: true            # false = 只看不回
      contextMessages: 6         # 每轮带上最近的几条
      groupTrigger: mention      # mention：@ 她／引用她／命中关键词才接；all：每句都接
      groupKeywords: []          # groupTrigger: mention 时算「在叫她」的词
      bindHomeSession: owner     # owner：主人私聊用家会话、群各自独立；all：都用；none：各建一个
      snowlumaHome: ''           # SnowLuma 安装目录，控制台那扇门用它找 config/runtime.json
      supervise: true            # 插件自己盯着这条线：端口不通就拉 SnowLuma（不用再建计划任务）
      # proactive: { enabled: false, dryRun: true }   # 主动开口，默认关，规则见 INSTALL.md
```

**改她的措辞**：世界提示词可以直接在控制台里改。闹钟响时、提前停下时、每日回顾时她收到的话，在世界目录里放一份 `alarm.md` 就能按段覆盖，段落名和可用的占位符见 `templates/alarm.md`。插件写给她的话一律用第一人称「我」，读起来是她自己的念头。

**时间**：建议把预设里 `time-context` 条目的 `refreshIntervalMs` 设为 `0`，让她每一步都知道现在几点。

## 她的东西放在哪

都在 `<DSH_HOME>/worlds/<worldId>/` 下（`DSH_HOME` 默认是用户目录下的 `.dsh`）：

| 位置 | 是什么 |
|---|---|
| `conversations/` | 按天归档的聊天原文（给人看的导出，正本在 `archive.sqlite`） |
| `room/` | 她的房间；`room/我是谁.md` 是她的自述 |
| `diary/` | 她的日记（可用 `diaryDir` 换位置） |
| `persona.md`、`world-prompt.md`、`alarm.md` | 你写给她的人设、世界提示词和闹钟措辞 |
| `world.json` | 世界是否在运行、每天额度、近期记忆轮数和选定归档范围 |
| `activity/` | 她在家里用过的工具，只记录，不进记忆 |
| `wechat.json` | 本机微信模块的地址、令牌和协议版本，不应公开 |
| `wechat-outbox.sqlite` | 微信工具安排的发送队列和确认状态 |
| `qq-native.json` | 控制台上 QQ 卡那几个开关的临时覆盖（会不会自己回话、主动开口、演练模式），盖在 profile 默认之上 |
| `qq-proactive.json` | 主动开口的账：今天发过几条、问过几次、连续失败几回 |
| `panel.json` | SnowLuma 控制台那扇门的登录票据，权限 600，不应公开 |

备份时整个目录一起备份即可，最好先停止 DSH。

## 桥与推送协议

给桌宠等本地程序用。

**把话送进她的家**（`bridge: true`）：插件启动时写出 `<世界目录>/bridge.json`，内容是 `{ origin, token, name, ... }`。向 `POST {origin}/dsh-world/bridge/say` 发 `{ "text": "..." }`，请求头带 `x-dsh-world-token: <token>`，会立即返回 `202`。这句话会作为你本人说的话进入她的家和记忆。

**接收她的话**（`outlets`）：每个目标写一个 `name`，地址用 `url`（其中 `{origin}` 会被替换），或者用 `urlFile` + `path`（端口会变的程序用这个）；再用 `kinds` 选择要接收哪些：`reply` 是桥上那句话的回复，`busy` 表示她正忙，`reach` 是她主动找你。插件会向目标 `POST`：

```json
{ "text": "她的话（纯文本）", "kind": "reply", "name": "她的名字", "images": ["http://…"], "image": "表情名" }
```

目标回复 2xx 就算送到。送不到的会显示在控制台的「健康」里。
